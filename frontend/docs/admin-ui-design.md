## 0. 核心决策摘要

1. **管理后台独立成 Shell**：桌面左侧固定导航（220px）+ 右侧内容区（最大 1120px）；移动端顶部栏 + 横向页签。管理路由隐藏底部 TabBar，页面自己管理安全区。
2. **按页面拆分，不再是一页卡片流**：`/admin`（概览）、`/admin/users`、`/admin/users/:id`、`/admin/audit`、`/admin/roles`、`/admin/invites`、`/admin/coach`。
3. **中文优先**：后台是沐禾运营团队的工作面，使用独立的后台文案包（zh 默认、en 保留），不污染现有 20 种语言的用户端字符串；事件码仍由后端存英文，前端做中文映射。
4. **权限用三种状态表达**：可见可用 / 可见但禁用并说明原因 / 完全隐藏。客服进入后台有持续只读横幅；需要更高角色的入口不渲染，状态不允许的操作禁用并给理由。
5. **5 分钟二次验证是全局能力**：`StepUpProvider` 持有服务端返回的 `stepUpUntil`；所有敏感请求统一走 `ensureStepUp(action)`，验证成功后自动重放原请求一次；顶部常驻验证状态与倒计时。
6. **删号改为“输入账户名 + 二次验证”**：不再用两层确认弹窗。不可逆操作需要主动输入目标名称，确认按钮才可用；二次验证嵌在同一个弹窗内，不叠加第二层弹窗。
7. **审计日志改成真正的表格**：桌面表格 + 吸顶表头、按天分组、失败才用红色、可展开行内详情；移动端降级为两行卡片。筛选状态写入 URL，可刷新、可回退、可分享。
8. **视觉克制**：沿用现有深色令牌与细分隔线，不引入新色板；只新增 4 个语义文字色令牌 + 1 个危险按钮前景色，解决浅色主题对比度问题（红/绿/黄/蓝在浅色下作为小字不合格）。
9. **成本控制**：停止 15 秒轮询整份用户列表（会读取每个用户的状态文件）；概览用聚合接口 + 轻量在线状态轮询，列表按需加载，审计不轮询。
10. **WebView 限制显式处理**：Capacitor WebView 内无法完成 passkey 仪式（现有代码已注明 origin 不匹配）。在 App 内打开后台时，只读页面正常；敏感操作弹窗改为“复制链接到浏览器完成”。

## 设计分析

### 1.1 现状

`frontend/src/views/Admin.jsx`（342 行）是单页卡片流：

```
页头（标题 + 用户数 + 刷新）
├─ 简介
├─ 4 个统计 tile
├─ Training now（实时训练）
├─ AdminCoach（AI 教练配置）
├─ InvitesCard（邀请码）
├─ Users（全量用户列表，点击开 sheet）
└─ AuditCard（活动日志，chips + Show more）
```

优点，必须保留：

- 每张卡片用一句话说明用途，半年看一次也能懂。
- 状态用词（admin / disabled / invite），不靠颜色猜。
- 危险操作写清楚后果，先给导出再给删除。
- 卡片、细分隔线、状态胶囊与全局设计语言一致。
- 统计 tile、列表行、chips、sheet 都有现成实现。

### 1.2 现有设计语言（可复用资产）

- **令牌**：`--bg #000`、`--bg-el #0e0e10`、`--surface #1c1c1e`、`--surface-2 #2c2c2e`、`--surface-3 #3a3a3c`；文字 `--label` / `--label-2` / `--label-3` / `--label-4`；分隔 `--sep`；强调 `--acc`（默认 `--green #30d158`）；状态 `--red #ff453a`、`--yellow #ffd60a`、`--blue #0a84ff`。
- **几何**：`--r-sm 8`、`--r 12`、`--r-card 14`、`--r-lg 16`、`--r-xl 22`；`--pad 16`；`--hair .5px`。
- **动效**：`--fast 140ms`、`--med 220ms`、`--ease cubic-bezier(.32,.72,0,1)`；按压 scale .975；全局 `prefers-reduced-motion` 关闭动画。
- **控件**：`Button`、`TextField`、`SearchField`、`NumberField`、`Stepper`、`Switch`、`Segmented`、`Check`、`Section`、`Row`、`Icon`（自绘 24×24 描边图标）。
- **容器**：`.card`、`.tiles/.tile`、`.list/.item`、`.chips/.chip`、`.sect`、`.lrow`。
- **后台专用**：`.adm-pill`、`.adm-lead`、`.adm-hint`、`.adm-empty`、`.adm-code`、`.adm-kv`、`.adm-actions`、`.adm-field`。
- **弹层**：`openSheet` / `confirmSheet`；`kind: 'center'` 为居中对话框，`locked` 禁止滑动/背景/返回关闭。
- **图表**：`LineChart` 支持 `series` 多线、`axes`、tooltip，viewBox 340 宽，可拉伸。

### 1.3 问题清单

| 问题 | 影响 | 处理 |
|---|---|---|
| 单页 342 行，所有功能纵向堆叠 | 找不到东西；无法深链；权限无法按页控制 | 拆分 7 个路由 |
| 全英文硬编码，`Admin.jsx` 注释明确“不进语言包” | 沐禾运营人员阅读成本高 | 独立后台中文文案包 |
| 只有 `admin` 布尔，没有角色 | 无法表达 super_admin / ops / support | 新增角色模型与权限矩阵 |
| 危险操作只有两层确认 sheet | 用户会连点穿过；没有身份再验证 | 输入名称确认 + step-up |
| 改配额、看训练明细没有二次验证 | 会话被拿走即可操作敏感数据 | 5 分钟 step-up |
| 用户列表全量加载、每 15 秒轮询 | 用户多时慢；每轮读所有状态文件 | 服务端分页 + 轻量概览轮询 |
| 审计是卡片 + “Show more” | 无法按管理员/动作/目标/时间筛选；列对不齐 | 表格 + 筛选栏 + URL 状态 |
| 时间、次要信息用 `--label-3`（约 2.6:1） | 小字对比度不合格 | 后台正文次要信息统一 `--label-2` |
| 加载态是 “Loading…” 文本 | 布局跳动、状态不明 | 骨架屏 + 保留旧数据刷新 |
| `UserDetail` 在 sheet 内直接渲染用户数据 | 曾有脏数据把整页打崩的注释记录 | 页面级 ErrorBoundary + 防御性渲染 |
| 居中弹窗仅 300/340px 宽 | 放不下删号影响清单与输入确认 | 后台对话框 440–520px，移动端底部 sheet |

### 1.4 约束与差异说明

- **背景色差异**：任务描述写 `#0c0e12`，仓库实际是 `--bg #000`、`--bg-el #0e0e10`。本设计以代码为准，不新增 `#0c0e12`。
- **技术栈**：React 19 + Vite + React Router 7（HashRouter）；Capacitor Android；无第三方组件库、无图表库；CSS 变量主题；`index.css` 已使用 `:has()`。
- **移动优先的 App，桌面优先的后台**：后台主要在桌面浏览器使用；移动端保证“能完成紧急操作”，但不为手机重排全部信息密度。
- **WebAuthn 限制**：`api/server.js` 明确 passkey 仪式无法在 App WebView 内完成（origin 与 RP_ID 不匹配）。后台在 App 内应可只读浏览；敏感写操作引导到浏览器。
- **权限是服务端的**：UI 的隐藏/禁用只是减少误操作，所有接口仍须服务端鉴权。
- **现有测试**：`Admin.test.jsx`、`Admin.password.test.jsx`、`AdminCoach.*.test.jsx` 会因路由与文案变化需要同步更新。

### 1.5 设计原则

1. **信息密度优先，装饰为零**：管理工具不是营销页；一屏能看到更多行、更多列、更多可比较的数字。
2. **状态用词，颜色辅助**：成功是安静的文字，失败才红；角色用图标 + 文字，不只靠颜色。
3. **确认强度与不可逆性匹配**：停用一次确认；改配额靠 step-up；删号靠“输入名称 + step-up”；清空日志靠“输入清空 + step-up”。
4. **权限差异要可解释**：不能让客服对着一排灰按钮猜。不能做的事隐藏；暂时不能做的事禁用并写原因。
5. **一次只做一件事**：不在删号弹窗上再叠一个验证弹窗；验证面板可复用在弹窗内部。
6. **复用优先**：能用的 `ui.jsx` 控件、`admin.css` 类、`LineChart` 一律复用；新样式集中在 `admin-console.css`，减少与上游合并的冲突面。

## 信息架构

### 2.1 路由表

| 路由 | 页面 | 角色 | 说明 |
|---|---|---|---|
| `/admin` | 概览 | 全部管理员 | 入口默认页；不再重定向 |
| `/admin/users` | 用户列表 | 全部管理员 | 搜索、角色/状态筛选、分页 |
| `/admin/users/:id` | 用户详情 | 全部管理员 | 脱敏视图；敏感区块按角色与 step-up 解锁 |
| `/admin/audit` | 审计日志 | 全部管理员 | 只读表格；support 隐藏 IP 列 |
| `/admin/roles` | 角色与权限 | super_admin | 其他角色直接进入 403 面板 |
| `/admin/invites` | 邀请码 | super_admin、ops | support 导航不渲染；直接访问 403 |
| `/admin/coach` | AI 教练 | super_admin、ops | 复用现有 `AdminCoach`，不改内部结构 |
| `/admin/*` | 兜底 | — | 重定向 `/admin` |

实现方式：`App.jsx` 中 `/admin/*` 挂 `AdminShell`，内部用 `<Routes>` 或 `<Outlet>`；`user?.admin` 仍是总开关。旧的 `/admin` 单页内容拆散后不再保留。

### 2.2 导航结构

**桌面（≥1000px）**

```
沐禾健身
管理后台
────────────────
运营
  概览
  用户
  审计日志
  邀请码
系统
  角色与权限      （仅 super_admin）
  AI 教练
────────────────
[头像] 常智
超级管理员
[锁] 已验证 04:12
返回应用
```

- 分组标题：11.5px / 600 / `--label-2`，字距 .04em；不使用 `--label-3`，因为 2.6:1 的小字不合格。
- 当前项：`--acc-soft` 背景 + `--acc` 文字 + 左侧 2px 圆角竖条。
- 不可见角色：整项不渲染；不要留灰色占位。
- 底部身份卡固定：头像、姓名、角色徽章、step-up 状态、返回应用。

**移动（<1000px）**

```
[‹]  管理后台              [锁 04:12]  [⋯]
概览   用户   审计   更多
```

- “更多”打开 sheet：邀请码、角色与权限、AI 教练、身份与验证状态、返回应用。
- 当前页签用下划线（2px `--acc`）而不是胶囊，减少视觉重量。
- 后台路由隐藏底部 TabBar；`#app` 的内边距由 Shell 接管。

### 2.3 页面职责

| 页面 | 回答的问题 | 首屏必须看到 |
|---|---|---|
| 概览 | 这个实例现在怎么样？有什么需要我处理？ | 5 个 KPI、14 天趋势、实时训练、需要关注项 |
| 用户列表 | 人在哪？谁异常？ | 总数、搜索、筛选、列表前 25 人、分页 |
| 用户详情 | 这个人是什么状态？我能对他做什么？ | 身份/状态、统计、配额、敏感数据锁、账户操作 |
| 审计日志 | 谁在什么时候做了什么？ | 总数、筛选、最近 50 条、按天分组 |
| 角色与权限 | 谁是管理员？各自能做什么？ | 角色说明卡、管理员表、授予入口 |
| 邀请码 | 还有哪些码可用？谁用了？ | 邀请制状态、可用/已使用、创建入口 |
| AI 教练 | 实例的教练怎么配置？ | 复用现有 AdminCoach 的配置流程 |

### 2.4 权限矩阵

| 能力 | super_admin | ops | support | 额外验证 |
|---|---|---|---|---|
| 查看概览 | 可用 | 可用 | 可用 | — |
| 查看营收明细 | 可用 | 可用 | 隐藏 | — |
| 用户列表 / 搜索 | 可用 | 可用 | 可用 | — |
| 用户详情（脱敏） | 可用 | 可用 | 可用 | — |
| 显示完整邮箱 | 可用 | 可用 | 隐藏 | step-up |
| 训练 / 体重 / 测量明细 | 可用 | 可用 | 隐藏 | step-up |
| 导出用户数据 | 可用 | 可用 | 隐藏 | step-up |
| 修改配额 | 可用 | 可用 | 隐藏 | step-up |
| 停用 / 启用 | 可用 | 可用 | 隐藏 | 一次确认 |
| 重置密码 | 可用 | 可用 | 隐藏 | step-up |
| 删除账户 | 可用 | 隐藏 | 隐藏 | 输入名称 + step-up |
| 邀请码管理 | 可用 | 可用 | 隐藏 | — |
| 审计日志查看 | 可用 | 可用 | 可用 | — |
| 审计 IP 列 | 可见 | 可见 | 隐藏 | — |
| 清空审计日志 | 可用 | 隐藏 | 隐藏 | 输入“清空” + step-up |
| 角色管理 | 可用 | 隐藏 | 隐藏 | step-up |
| AI 教练配置 | 可用 | 可用 | 隐藏 | 保存密钥时 step-up |
| 授予 / 撤销 super_admin | 仅服务器配置 | — | — | — |

说明：

- **super_admin 只能由服务器配置调整**。UI 只允许授予/撤销 ops 与 support，避免在界面里做不可回退的提权。若后端已定稿允许 UI 授予 super_admin，角色页只需多一个角色卡，权限模块不变。
- **ops 不能删号**是本设计的建议。若后端定稿允许，只需在 `permissions.js` 打开，UI 结构不变。
- **support 看不到营收和 IP** 是默认最小权限；若运营要求客服也能看，改矩阵即可。
- 角色的实际字段名待定（建议 `user.admin_role`）；旧数据 `admin === true` 且无角色时，UI 映射为 super_admin。

### 2.5 路由守卫与 403

```
未登录               → 现有登录流程
user.admin !== true  → <Navigate to="/home" replace />（保持现状）
角色不足             → 页面内 403 面板（不重定向）
资源不存在           → 404 面板
step-up 失效         → 弹窗，不换页
```

403 面板：

```
        [盾牌图标]
        没有访问权限
   你的角色是「客服」，此页面仅超级管理员可见。
   [返回概览]   [了解角色权限]
```

为什么不重定向到首页：操作者需要知道“为什么进不去”，而不是以为链接坏了。

### 2.6 登录、身份与入口

- **没有独立的“管理员登录页”**。管理员就是普通用户，使用现有通行密钥登录流程；登录成功后，`/api/admin/session` 返回 `role` 与 `stepUpUntil`。
- **入口**：设置 → 账户 → “管理后台”（`settings-pages.js:138`、`Settings.jsx:846/866`），以及直接访问 `/admin`。App 与浏览器共用同一个入口。
- **身份映射**：旧数据只有 `admin: true` 时，UI 视为 `super_admin`；新字段建议 `admin_role`。第一个用户自动成为管理员的服务端行为保持不变。
- **非管理员**：`/admin` 仍重定向 `/home`；管理员但角色不足：页面内 403。
- **被停用账户**：无法登录，因此也进不了后台；已有会话由服务端失效。
- **App WebView**：只读页面可正常使用；敏感写操作需要 passkey 时引导到浏览器（见 4.7.1）。
- **后台不提供“切换身份”**：角色由服务器或其他 super_admin 授予；操作者不能临时提权。

### 4.4 表格规范（审计日志与用户列表）

这是本次设计的重点之一。

**桌面表格**

- 容器：`--surface`，圆角 14，`overflow: hidden`。
- 表头：36px 高，`position: sticky; top: 0`，背景 `--surface`，下边 0.5px `--sep`；12px/600/`--label-2`。
- 行：48px 最小高；`border-bottom: var(--hair) solid var(--sep)`；整行可点击（用户）或可展开（审计）。
- 悬停：仅 `@media (hover: hover)`，背景 `color-mix(in srgb, var(--surface-2) 45%, transparent)`。
- 聚焦：整行 `box-shadow: inset 0 0 0 2px var(--acc)`，因为 outline 会被容器裁掉。
- 数字列右对齐、等宽；文本左对齐；结果列左对齐。
- 不在行上做斑马纹；用细线分隔。
- 用户表列宽：用户 `1fr`（最小 240）、角色 110、状态 90、训练数 80（右）、最后同步 120、加入时间 110、操作 48。
- 审计表列宽：时间 96、操作者 140、动作 `1fr`（最小 180）、目标 140、结果 72、IP 110、展开 36。
- 宽度不足：先隐藏“加入时间”（用户）与“来源 IP”（审计），再降级为卡片；不横向滚动整页。

**审计按天分组**

- 日期组头 32px 高，12/600/`--label-2`，背景 `--surface`，`position: sticky; top: 36px`；文案“今天 / 昨天 / 10-20”。
- 组头不是可点击行，不参与 hover。
- 跨天时时间列只显示 `HH:mm:ss`；完整时间在展开详情里。

**审计可读性规则**

1. 时间等宽、右对齐、永不截断。
2. 操作者与目标：姓名优先，超长省略，`title` 给全名 + ID。
3. 动作标签用中文短句（“修改用户配额”“停用账户”），不用原始事件码；原始码放展开详情。
4. 分类用 6px 圆点：登录 `--info-text`、管理 `--acc`、媒体 `--purple`、未知 `--label-3`。
5. 结果只区分“成功 / 失败”：失败用 `--bad-text` + 12% 红底胶囊；成功用 `--label-2` 文本，不刷绿。
6. 展开详情：2 列定义列表（时间、操作者、目标、变更、事件 ID、结果原因、IP/UA），下面折叠“查看原始 JSON”；提供复制按钮。
7. 行展开用 `aria-expanded`，Enter/Space 可切换；展开后焦点留在触发按钮。
8. 筛选后空态：“没有匹配的事件” + “重置筛选”，不是“还没有日志”（两者文案不同）。
9. 加载更多按钮 36 高居中；加载后 `aria-live="polite"` 宣布“已加载 50 条，共 12,480 条”。
10. support 不渲染 IP 列；展开详情也不显示 IP。

**用户表可读性**

- 姓名 14/500，邮箱 12.5/`--label-2`，两行单元格。
- 头像 32px 圆，`--surface-2`，首字；管理员可加 1px 角色色描边（可选，不必须）。
- 状态：圆点 + 文字；停用行不整行降透明度（现有做法会让可读性变差），只让姓名变 `--label-2`。
- 行尾“…”始终可见，不靠 hover 才出现。
- 目标行是管理员时，菜单里的停用/删除置灰并写原因。

### 4.6 权限的 UI 表达规范

**三条渲染规则**

1. **角色永远不能做的**：不渲染。导航项、按钮、整块卡片都适用。不要留灰按钮让客服反复点。
2. **角色能做、但当前状态不允许的**：渲染为禁用，并在按钮下方或 `title` 写明原因。例：最后一个超级管理员不能撤销；管理员目标不能停用；离线时不能保存。
3. **角色能做、但需要 step-up 的**：正常渲染；点击后走验证。不要提前把按钮变灰，那会让操作者以为没权限。

**support 只读的具体表达**

- 进入后台时，内容区顶部出现只读横幅：

```text
[锁] 只读模式 · 你的角色是客服，可以查看数据，不能修改。
```

- 横幅不刺眼：`--surface` 背景、12.5px、`--label-2`，无红黄。
- 用户详情底部不渲染账户操作卡，替换为一行说明：“只读角色不能修改账户。需要操作请联系超级管理员或运营。”
- 审计页不渲染 IP 列；不渲染清空入口。
- 邀请码与角色页在导航中不渲染；直接访问显示 403。
- 所有隐藏都只是 UI；接口仍返回 403。

**角色徽章**

- 超级管理员：皇冠图标 + “超级管理员”，`--acc-soft` / `--acc`。
- 运营：扳手图标 + “运营”，`--info-text` 12% 底 / `--info-text`。
- 客服：人形图标 + “客服”，`--surface-2` / `--label-2`。
- 普通用户：不显示徽章；用户表里用 `--label-2` 文本“普通用户”。

**权限变更的运行时处理**

- 任何接口返回 403（非 step-up）时：重新拉取 `/api/admin/session`；若角色变化，显示一条顶部横幅“你的权限已更新”，并刷新导航；若已无权限，进入 403 面板。
- 不静默重试 403；不把用户踢回首页。
- 角色撤销后，对方下一次请求即失效；文案不要承诺“立即退出”，只说“新权限对之后的请求生效”。

### 4.7 交互设计

#### 4.7.1 二次验证（step-up）时序

**前置**

- 服务端在验证成功后返回 `stepUpUntil`（epoch ms），并在每个敏感接口上校验；客户端只在内存中镜像，不写 localStorage。
- 窗口固定 5 分钟，不因每次操作而延长；到点重新验证。
- 顶部 StepUpChip 每 10 秒刷新一次倒计时（后台标签页节流，恢复可见时立即重算）；剩余 <60s 变琥珀色。

**正常路径**

```text
操作者                  Admin UI                     服务端                  认证器
  │ 点击「保存配额」        │                            │                       │
  │──────────────────────>│ stepUpUntil > now ?         │                       │
  │                       │  ├─ 是 -> 直接发请求 ──────>│                       │
  │                       │  └─ 否 -> 打开验证弹窗      │                       │
  │ 点击「使用通行密钥验证」 │                            │                       │
  │──────────────────────>│ POST /admin/step-up/options ───────────────────────>│
  │                       │<──────── challenge ────────────────────────────────│
  │                       │ navigator.credentials.get() ──────────────────────>│
  │                       │<──────── assertion ────────────────────────────────│
  │                       │ POST /admin/step-up/verify ────────────────────────>│
  │                       │<──────── { until } ────────────────────────────────│
  │                       │ 记录 until，关闭验证弹窗     │                       │
  │                       │ 重放挂起的请求 ────────────>│                       │
  │                       │<──────── 200 ───────────────│                       │
  │ 看到「已更新配额」toast │                            │                       │
```

**服务端 403 兜底**

```text
请求 -> 403 { code: 'step-up-required' }
  -> ensureStepUp(actionSummary)
     -> 成功：重试原请求一次
     -> 失败/取消：放弃，保留原表单状态
  -> 重试仍 403：停止，显示错误，不循环
```

**并发与去重**

- 同一时刻只允许一个验证弹窗；打开时其他敏感点击被忽略。
- 最多保留一个“待执行动作”；新动作覆盖旧动作前先提示（实际 UI 中被弹窗挡住，不会发生）。
- 请求进行中禁用触发按钮，避免重复提交。

**弹窗状态**

| 状态 | 画面 | 可关闭 |
|---|---|---|
| 空闲 | 说明 + 即将执行摘要 + 主按钮 | 是（取消 / Esc / 背景） |
| 验证中 | 主按钮 busy，浏览器原生 passkey 提示覆盖 | 否（等待原生结果） |
| 失败 | 红色内联文案“验证未完成，请重试” | 是 |
| 用户取消 | 中性文案“验证已取消” | 是 |
| 成功 | 短暂对勾 200ms，关闭并执行 | — |

**无 passkey / WebView**

- 若实例提供密码登录：主按钮下方显示“改用密码验证”。
- 若在 Capacitor WebView 内且 WebAuthn 不可用：不显示主按钮，改为

```text
敏感操作需要在浏览器中完成。
[复制管理后台链接]  [取消]
```

- 只读浏览不受影响。

**主动验证**

- 点击 StepUpChip 打开一个小弹层：说明 5 分钟窗口、当前剩余时间、按钮“立即验证”。
- 验证成功只刷新 chip，不执行任何动作。

#### 4.7.2 危险操作：删除账户

**为什么不用两层确认 sheet**

现有实现是“Continue -> Delete account”两层。操作者会形成肌肉记忆连点，第二层并不构成真正的确认。改为“输入账户名”的主动摩擦，只有名称完全匹配，最终按钮才可用。

**流程**

```text
用户详情 -> 删除账户
  -> 打开 DangerConfirm
     ├─ 展示影响清单（训练/体重/测量/例行/通行密钥/推送/媒体）
     ├─ [下载其数据]（本身触发 step-up；下载后弹窗保留）
     ├─ 输入账户名「张伟」
     │    ├─ 不匹配：输入框红边 + “名称不匹配”，按钮禁用
     │    └─ 匹配：最终按钮启用
     -> 点击「永久删除账户」
        ├─ step-up 有效：直接执行
        └─ step-up 失效：弹窗内切换为验证面板
             -> 验证成功：自动执行删除
             -> 验证失败：留在验证面板，可重试或取消
  -> 成功：关闭弹窗，toast「已删除 张伟」，返回用户列表并刷新
  -> 失败：错误留在弹窗内；404 提示“该用户可能已被删除”；403 提示权限/角色变化
```

**视觉**

- 顶部 40px 红色软底圆 + 警示图标；标题 20/600；副文案“此操作不可撤销”。
- 影响清单用 13.5px，每行一条；数字等宽。
- 输入框 44 高，标签可见，`aria-describedby` 指向错误文案。
- 最终按钮：实心 `--red` + 黑字（对比度 6.2:1），只在匹配后启用。
- 底部一行 12.5px `--label-2`：“删除操作将记录到审计日志。”
- 弹窗打开时初始焦点在“取消”，不是输入框；避免误输入。输入框获得焦点后，回车不提交，必须点击匹配后的按钮。

**服务端仍要拒绝**

- 删除自己。
- 删除最后一个超级管理员。
- 非 super_admin。
- step-up 失效。
UI 的错误处理要能显示这些服务端原因，不自行假设。

**其它危险操作**

| 操作 | 确认方式 | step-up |
|---|---|---|
| 停用账户 | 单次确认，说明“立即退出所有设备、数据保留” | 否 |
| 启用账户 | 无需确认，直接执行 | 否 |
| 撤销管理员 | 确认，列出失去的权限 | 是 |
| 清空审计 | 输入“清空” + 确认 | 是 |
| 修改配额 | 无额外确认，保存即执行 | 是 |
| 重置密码 | 确认，说明旧密码立即失效、通行密钥仍可用 | 是 |
| 导出用户数据 | 确认，说明包含个人信息 | 是 |

#### 4.7.3 配额编辑

**布局**（见 3.12）

- 每个配额一行：名称（14/600）、当前用量（12.5/`--label-2`）、4px 用量条、步进器、单位、默认值说明。
- 步进器复用 `Stepper`（44 高按钮、可长按加速、可输入）。宽度 148px；单位在字段内右侧。
- 输入语义（必须与后端一致，UI 明示）：
  - 数字：显式配额。
  - 留空：继承实例默认值（placeholder 显示默认值）。
  - 0：关闭该能力（文案“0 = 关闭”）。
- 用量条：已用/配额；≥90% 变 `--warn-text`，100% 变 `--bad-text`；条本身颜色同步，但数字始终显示。
- 脏状态：卡片底部出现操作条“有未保存的更改 [放弃] [保存]”，并给卡片标题一个 6px 的 accent 点。
- 保存按钮：无更改或校验失败时禁用。
- 保存流程：
  1. 前端校验（整数、范围、空值）。
  2. 若 step-up 有效：直接 POST；按钮 busy；成功 toast “已更新配额：AI 每日消息 20 -> 50”；卡片刷新。
  3. 若失效：打开 StepUpDialog，摘要列出全部变更（旧 -> 新，多行）；验证成功自动重试保存。
  4. 409（其他管理员已改）：内联提示“配额已被其他管理员修改，已刷新为最新值”；整卡刷新并丢弃脏状态（提示里写明），不悄悄合并两个管理员的编辑。
- 不允许乐观更新：敏感数据以服务端返回为准。

#### 4.7.4 角色授予与撤销

**授予**

1. 点击“授予管理员”打开 `GrantRoleDialog`（桌面 520px，移动全高 sheet）。
2. 搜索用户（300ms 防抖）；结果行显示姓名、脱敏邮箱、当前角色；已是管理员的用户标注“已是管理员”，不可选。
3. 选择角色卡（运营 / 客服），单选；卡片内列出能力清单。
4. 点击“授予角色”：
   - 需要 step-up（提权属于敏感操作）。
   - 验证成功后 POST；成功关闭，刷新管理员表，toast “已授予 张伟 运营角色”。
5. 服务端拒绝（用户不存在、已是管理员、无权限）显示在弹窗内。

**撤销 / 变更**

- 行菜单 -> “变更角色” 或 “撤销管理员”。
- 确认弹窗列出“将失去：改配额、停用账户、邀请码管理……”（变更时同时列出获得项）。
- step-up 后执行。
- 超级管理员行没有操作；页面说明原因。
- 不能撤销自己（当前用户是 super，本来也不在可操作行内）。

#### 4.7.5 敏感数据解锁

- 默认锁定；锁面板显示原因与按钮。
- 点击“使用通行密钥查看” -> StepUpDialog（摘要“查看 张伟 的训练明细”）-> 成功 -> 请求明细接口 -> 渲染。
- 解锁后卡片头：`已验证 04:12` + “重新锁定”。
- 5 分钟到点：清空组件内的敏感数据（不只是模糊），恢复锁定面板，文案“验证已过期，重新验证以查看”。
- 路由离开即清空。
- 邮箱“显示完整”同理，单独 step-up；显示后不自动隐藏，但离开页面即失效。

#### 4.7.6 筛选、分页与刷新

- 用户列表：服务端分页，页码写入 URL；搜索 300ms 防抖；筛选变化重置到第 1 页。
- 审计：游标“加载更多”，因为新事件会从头部插入，页码会漂移；筛选写入 URL。
- 筛选 chips：已应用条件显示为可移除胶囊；“重置”清空全部。
- 刷新：保留旧数据，顶部显示 2px 不确定进度条 + “更新中…”，完成后更新时间；失败保留旧数据并显示错误卡。
- 概览：每 30 秒刷新 KPI 与实时训练，仅当标签页可见；图表与营收 5 分钟缓存。不要轮询整份用户列表。
- 审计不自动轮询；手动刷新。

#### 4.7.7 键盘

| 按键 | 行为 |
|---|---|
| `/` | 聚焦当前页搜索框（用户/审计） |
| `Esc` | 关闭最上层弹窗/弹层；不提交 |
| `Enter` | 在表格行上打开详情/展开；在表单中提交（危险操作除外） |
| `Tab` / `Shift+Tab` | 正常焦点顺序；弹窗内陷阱 |
| `Space` | 展开审计行；切换选中 |
| `Cmd/Ctrl + Enter` | 配额卡保存（可选，P2） |

不要发明大量单键快捷键；后台以鼠标为主。

### 4.8 状态设计

#### 4.8.1 页面级状态

| 页面 | 初始加载 | 刷新 | 空 | 无筛选结果 | 错误 | 无权限 |
|---|---|---|---|---|---|---|
| 概览 | 5 个 KPI 骨架 + 图表 180px 骨架 | 保留旧值，细进度条 | 图表“还没有活动”；KPI 显示 0 | — | 卡片级“暂不可用”，其余照常 | 403 |
| 用户列表 | 8 行骨架 | 保留旧列表，顶部进度条 | “还没有用户” + 创建邀请码 | “没有匹配的用户” + 清除筛选 | `role=alert` 错误卡 + 重试；保留上次列表 | 403 |
| 用户详情 | 头 + 卡片骨架 | 局部刷新 | 新用户：统计为 0，训练明细“还没有训练记录” | — | 错误卡；404 专用面板 | 403 |
| 审计 | 10 行骨架 | 保留旧表 + 进度条 | “还没有审计事件” | “没有匹配的事件” + 重置 | 错误卡 + 重试 | 403；未启用则说明 |
| 角色 | 3 张卡 + 表骨架 | 局部 | “只有你一位管理员” + 授予入口 | 搜索无结果 | 错误卡 | 403 |

#### 4.8.2 组件级状态

- **按钮**：默认 / hover / active / focus-visible / disabled / busy。
- **输入**：默认 / focus（2px `--acc` 内阴影）/ invalid（红边 + 文案）/ disabled。
- **行**：默认 / hover（仅指针设备）/ focus（内描边）/ 展开（`--surface-2` 60%）/ 禁用（文字 `--label-2` + 原因）。
- **StepUpChip**：未验证（`--surface-2` + `--label-2`）/ 已验证（`--acc-soft` + `--acc`）/ 即将过期（`--warn-text`）/ 过期（同未验证）。
- **同步/网络**：离线时顶部细条“无法连接服务器，正在重试…”；写操作失败不假装成功。
- **会话过期**：整页面板“登录已过期，请重新登录”，按钮回登录；保留 `next=/admin/...`。
- **角色变化**：顶部横幅“你的权限已更新”，刷新导航与页面；不静默失败。

#### 4.8.3 空态文案原则

- 区分“还没有数据”和“筛选后没有结果”。
- 空态必须给下一步动作（创建邀请码、清除筛选、返回列表）。
- 不用插画；用 1 个 48px 图标圆 + 两行文字，与现有 `.empty` 语言一致。

### 4.9 可访问性考虑

#### 对比度

见 4.2.1 的实测表。要点：

- 后台所有可读文字至少 4.5:1；`--label-3` 不用于文字。
- 浅色主题必须使用新的 `--ok-text` / `--bad-text` / `--warn-text` / `--info-text`，不能直接用系统绿/红作为小字。
- 主按钮文字用 `--on-acc`（绿底黑字 10.4:1），不要白字（2.0:1）。
- 危险实心按钮用黑字（6.2:1），不用白字（3.4:1）。
- 禁用态可以低于 4.5:1（WCAG 豁免），但必须同时有文字原因，不能只靠透明度。

#### 焦点与键盘

- 全局 `:focus-visible` 已有 2.5px `--acc` 外环；表格行改用 inset 环避免被裁。
- 弹窗：打开时记录触发元素，关闭后焦点归还；`role="dialog" aria-modal="true" aria-labelledby`；Tab 陷阱；Esc 关闭（验证进行中除外）。
- 危险确认初始焦点在“取消”；step-up 初始焦点在“使用通行密钥验证”。
- 行可点击时使用 `<tr tabindex="0">` 或按钮包裹，Enter/Space 触发；展开按钮带 `aria-expanded`。
- 表头 `scope="col"`；表有 caption（视觉隐藏）；时间用 `<time datetime>`。
- 筛选结果数量变化用 `aria-live="polite"` 宣布（“找到 18 位用户”）。
- 图标按钮必须有 `aria-label`；角色徽章的文字必须存在，不能只有颜色。

#### 触控

- 移动端所有可点目标 ≥44px；表格卡片整卡可点。
- 桌面行内“…”视觉 28px，点击热区用伪元素扩到 36px。
- 不依赖 hover 才显示关键操作。

#### 动效

- 遵循全局 `prefers-reduced-motion`；骨架、呼吸点、弹窗缩放全部关闭。
- 不使用闪烁强调错误；用静态红字 + 图标。

#### 语言与读屏

- 后台文案跟随 UI 语言（默认 zh），`lang` 属性由根节点决定；中文页面不要用英文缩写作为唯一标签。
- 金额、百分比、日期由 `Intl` 输出；不要手工拼接。
- 角色、状态、结果都要有可读文本，读屏不依赖颜色。

## 附：设计决策的理由（简版）

- **为什么拆页而不是继续单页**：用户管理需要分页与筛选，审计需要筛选与展开，角色需要独立权限；单页会让 URL 无法表达状态，也无法做路由级 403。
- **为什么桌面用侧栏**：后台是长时间、跨页面的扫描型工作；侧栏提供稳定的位置记忆，顶部页签在 6 个入口时已经拥挤。
- **为什么中文后台**：上游的“English-only operator surface”是给个人实例主的；沐禾的运营是中文团队，英文会直接降低处理速度。独立字典避免污染 20 个语言包。
- **为什么删号要输入名称**：两层确认会被肌肉记忆穿透；输入名称要求操作者读取目标身份，是低成本、高收益的摩擦。
- **为什么 step-up 不叠弹窗**：删号弹窗内嵌验证面板，保留已输入的名称与影响清单；叠两层弹窗会让人不知道自己在确认什么。
- **为什么审计成功不刷绿**：日志里大多数是成功；全绿会让红色失败淹没在噪音里。安静的成功、突出的失败，才是可扫描的日志。
- **为什么新增语义文字色**：现有浅色主题把系统绿/红直接当小字用，对比度不合格；后台信息密度高、字号小，必须先解决可读性。
- **为什么列表分页、审计游标**：用户列表是稳定集合，需要页码与总数；审计是持续插入的流，页码会漂移，游标才能不重不漏。
